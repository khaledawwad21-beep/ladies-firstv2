# Stability and security audit — 13 October 2026

Baseline: `f1b64eb2bf8baa855e2401eb77ffce1f042c2e03` on main.

## Confirmed defects addressed

- **Daily AI quota bypass (cost/abuse):** `/api/ai/chat` only enforced a short-window limit, while `/api/ai/store-chat` also enforced the daily quota. Both now consume the same atomic database counter and account/guest identity. The existing owner exemption and Jerusalem calendar day are preserved. A quota database failure does not call the provider.
- **External requests from a regression test:** the shared short-window-limit test omitted `fetchImpl` and could call the real provider with a synthetic test key. Injected responses now isolate it. The npm test entry point preloads a guard that rejects external fetch calls and fails the process even if application error handling catches the rejection.
- **Welcome popup timer leak:** closing the popup left its interval alive until the campaign expiry. Closing now clears the interval, is idempotent, and prevents a queued animation frame from locking scroll after dismissal. Showing on a new visit is preserved.
- **Dead duplicate search function:** removed the earlier, shadowed `clearSearchAutofill` declaration. The existing active implementation remains authoritative. Updated frontend cache versions.

## Evidence

- Full suite with external-fetch guard: 384 tests, 377 passed, zero failed, seven explicitly skipped real-PostgreSQL integration tests.
- Subsequent targeted verification after search cleanup and lifecycle-test addition: nine tests passed, zero failed. Includes concurrent requests across both AI endpoints against isolated PGlite SQL, quota day rollover, guest identity, owner exemption, database outage, and popup close before/after its first animation frame.
- Updated two existing source-shape checks to follow the new cache version and carousel function boundary after duplicate removal; final full-suite counts above include these changes.
- Read-only live smoke verified main baseline storefront, admin HTML, database health and public catalog/settings/category/brand APIs.
- Common private-key/token pattern scan of tracked text sources found zero matching files; this does not scan git history.
- Existing suite covers authentication/session revocation, staff permissions, public-order access, waitlist privacy, input rendering, stock, orders, cancellations, returns, discounts, shipping, themes, category image preservation, and mobile interaction wiring.
- Dependency audit: zero known advisories at audit time. This is not a claim about unknown vulnerabilities or remote CDN assets.

## Remaining limits

- Seven real-PostgreSQL lifecycle tests require the isolated PostgreSQL CI service; PGlite is not a substitute for those gates.
- No real paid AI, WhatsApp, payment, refund, or biometric-device transaction was performed.
- No production customer records were modified. Infrastructure permissions, backup restore, secret history, and device/browser end-to-end behavior are not certified by this review.
- Legacy inline handlers, localStorage bearer sessions, permissive script CSP, and unpinned model-viewer CDN remain architectural hardening work. Avoid an untested broad rewrite during this repair.
- Passing tests do not establish that the entire application is vulnerability-free. This branch must pass CI and be deployed before its fixes affect production.
